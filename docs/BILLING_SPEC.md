# EcoStance AI Agent - Billing & Tier Specification (v1.0)

This document provides the technical requirements for the Frontend Developer to implement the **Pricing Grid** and **Billing Dashboard**.

## 1. Tier Overview & Identifiers
The system uses three primary backend identifiers. **It is critical to use these exact strings when calling the API.**

| Public Name | Backend Key (`billing_tier`) | Target Audience |
| :--- | :--- | :--- |
| **Free Trial** | `free_trial` | New users (14-day limit) |
| **Business** | `business` | Standard professional users |
| **Enterprise** | `enterprise` | High-volume & Custom needs |

## 3. Resource Quotas & Limits

## 4. Technical Logic for UI Enforcements

### A. The "Neutral Agent" Rule
For `free_trial` and `business` tiers, the frontend should **disable** the "System Prompt" or "Custom Instructions" input fields. 
*   **Logic**: These tiers only adopt the `company_name` from the branding settings.
*   **API Interaction**: The backend will ignore any `custom_system_prompt` sent for these tiers.

### B. Tool Gating
The "Tool Selection" UI should be restricted based on tier:
*   **Business Users**: Can only toggle "Knowledge Base".
*   **Enterprise Users**: Can see and configure "Custom API Webhooks" or "Developer Proxies".

### C. Trial Banner
For tenants where `billing_tier == "free_trial"`, the frontend should calculate the remaining days using the `trial_ends_at` field returned in the `/api/v1/tenants/register` or `/api/v1/auth/me` response.

## 5. API Reference Summary

*   **Registration**: `POST /api/v1/tenants/register`
    *   Payload: `{ "billing_tier": "free_trial", ... }`
*   **Upgrade Tenant (Admin)**: `PATCH /api/v1/admin/tenants/{tenant_id}/tier?tier=business`
*   **Check Usage**: `GET /api/v1/quotas/usage`
    *   Returns percentage progress bars for Queries and Storage.
